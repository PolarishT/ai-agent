Deployment Guide

部署文档

基于 RAG 的多模态电商智能导购 AI Agent —— 服务端从零到上线的完整部署指南：环境准备、配置、数据库初始化、构建、本地运行、Kubernetes 部署与可观测性接入。

Java 25 (GraalVM CE) Spring Boot 4.0.6 Spring Modulith 2.0.5 Spring AI 2.0.0-M4 Alibaba Graph 1.1.2 PostgreSQL Milvus RocketMQ 5.x Doubao Ark

#0 服务概览

本服务是一个 Spring Modulith 模块化单体：一个可独立部署的 Spring Boot 应用，内部按领域边界拆分为 document / indexing / graph 三个业务模块，以及 common / shared / infrastructure 三个横切模块。它对外只暴露一个 HTTP 服务进程（默认端口 8080，上下文路径 /api/v1），承载两条核心链路：

离线链路document / indexing
→
商品 & 文档切块 · 向量化
→
PostgreSQL + Milvus可检索知识库
→
在线链路graph (Agent 编排)
→
SSE 流式回答导购对话

部署一套完整环境需要：1 个应用进程 + PostgreSQL（主存）+ Milvus（向量库）+ RocketMQ（离线索引消息）+ 一个 OpenAI 兼容的大模型/Embedding 服务（竞赛使用火山方舟 Doubao）。其中 Milvus 与 RocketMQ 均可关闭并自动降级（见 §11），便于最小化起步。

阅读建议

本文档负责"如何把服务跑起来"。链路内部如何工作请看 《离线 / 在线链路技术文档》；按场景走一遍完整体验请看 《E2E 体验指南》。

#2 依赖中间件

下列外部依赖按"是否必须"分级。最小可运行集只需 PostgreSQL + 一个 LLM/Embedding 端点。

组件必需性用途关闭时的行为

LLM + Embedding
(OpenAI 兼容)		必需意图识别、槽位/条件抽取、答案生成、向量化。竞赛用火山方舟 Doubao意图与答案退化到规则兜底，检索仅关键词

SMTP可选索引最终失败 / 消息解析失败邮件告警通知开关默认关闭，不影响主流程
Elastic APM / OTLP可选分布式追踪、指标、日志上报仅本地控制台日志，无远程上报
最小起步

只想快速跑通：起一个 PostgreSQL + 填好 Doubao Key，把 RAG_MILVUS_ENABLED 与 RAG_ROCKETMQ_ENABLED 设为 false 即可。检索走关键词、索引走进程内，链路依然端到端贯通。

#5 数据库初始化

权威 schema 是 scripts/rag/pgsql/full_schema.sql，共 25 张表，覆盖 RAG 索引、会话、电商域全部对象。

5.1 表清单

RAG / 索引

rag_documents · rag_chunks · rag_index_jobs · rag_index_job_transitions · rag_index_outbox · rag_index_message_failures · rag_users

会话 / Agent

agent_conversations · agent_conversation_messages · agent_turn · agent_context_items · rag_ask_runs

商品目录

catalog_product · catalog_sku · catalog_product_knowledge · catalog_product_faq · catalog_product_review · catalog_attribute_outbox

购物车 / 订单

shopping_cart · cart_item · cart_transition_audit · customer_order · order_item · delivery_address · mock_orders

5.2 两种初始化方式

方式 A — 手动建库（生产推荐）：直接对目标库执行权威脚本，并禁用应用启动期初始化。

shell
psql "$PGURL" -f scripts/rag/pgsql/full_schema.sql
# 关键词检索增强（可选但推荐）
psql "$PGURL" -f scripts/rag/pgsql/enable_pg_trgm.sql
psql "$PGURL" -f scripts/rag/pgsql/enable_catalog_evidence_text_indexes.sql

方式 B — 应用启动期初始化（本地便捷）：设置 SPRING_SQL_INIT_MODE=always 并把 schema 放到 classpath，由 Spring Boot 启动时执行。

生产请关闭启动期初始化

Kubernetes 清单 k8s/server.yaml 已将 SPRING_SQL_INIT_MODE 设为 never——生产环境务必预先手动应用 schema，避免多副本并发执行初始化脚本。

5.3 pg_trgm 与全文检索

关键词检索路径在 PostgreSQL 上使用 to_tsvector('simple', …) + plainto_tsquery，并可叠加 pg_trgm 相似度兜底。scripts/rag/pgsql/ 下附带 explain_* 与 benchmark_* 脚本用于验证执行计划与基准。

#7 本地运行

  1. 同步代码 + 准备 .env（见 §3、§4）。
  2. 方式一：Maven 直跑（开发）
    shell
    ./mvnw spring-boot:run
  3. 方式二：Jar 启动（贴近生产，带 APM Agent）
    shell
    java -javaagent:./elastic-otel-javaagent.jar \
     -Dotel.sdk.disabled=true \
     --enable-native-access=ALL-UNNAMED \
     --sun-misc-unsafe-memory-access=allow \
     -jar target/ai-agent-0.0.1-SNAPSHOT.jar
    将 otel.sdk.disabled 置 false 并配置 otel.exporter.otlp.* 后即开启上报（见 §9）。
  4. 验证启动成功——日志应出现 embedding 绑定行，确认模型/维度正确：
    log
    RAG embedding 绑定：modelName=doubao-embedding-vision-250328,
  beanType=OpenAiEmbeddingModel, milvusEmbeddingDimension=2048
    若 beanType=<none> 或维度对不上，先解决再继续，否则索引会无声失败。
  5. 冒烟测试（注意上下文路径 /api/v1）：
    shell
    curl -s http://localhost:8080/api/v1/actuator/health

#8 容器 / Kubernetes 部署

仓库提供生产级清单 k8s/server.yaml：Namespace + ConfigMap + Secret + Deployment（2 副本，滚动更新）+ ClusterIP Service。

8.1 构建镜像

仓库未内置 Dockerfile，可用如下分层镜像（基于 GraalVM/JDK 25 运行时）：

Dockerfile
FROM container-registry.oracle.com/graalvm/jdk:25 AS run
WORKDIR /app
COPY target/ai-agent-0.0.1-SNAPSHOT.jar app.jar
COPY elastic-otel-javaagent.jar otel-agent.jar
EXPOSE 8080
ENTRYPOINT ["java","-javaagent:/app/otel-agent.jar", \
  "--enable-native-access=ALL-UNNAMED", \
  "--sun-misc-unsafe-memory-access=allow","-jar","/app/app.jar"]
shell
./mvnw clean package -DskipTests
docker build -t your-registry.example.com/rag/backend:1.0 .
docker push  your-registry.example.com/rag/backend:1.0

8.2 部署

  1. 编辑 k8s/server.yaml：替换 backend-secret 中的占位（PGPASSWORD / OPENAI_API_KEY / SPRING_AI_OPENAI_BASE_URL 等），并把 image 指向你推送的镜像。
  2. 预先对目标 PostgreSQL 应用 schema（§5）。ConfigMap 中 SPRING_SQL_INIT_MODE=never。
  3. 按需在 ConfigMap 打开 RAG_MILVUS_ENABLED / RAG_ROCKETMQ_ENABLED 并填端点。
  4. 应用清单：
    shell
    kubectl apply -f k8s/server.yaml
kubectl -n rag rollout status deploy/backend

#9 可观测性接入

采用 Elastic APM Java Agent 统一接管 Trace / Metrics / Logs，Spring Boot 内置 OTel exporter 全部禁用以避免双重上报。

能力实现配置
Trace / Metrics / Logs-javaagent:elastic-otel-javaagent.jarotel.exporter.otlp.endpoint / otel.exporter.otlp.headers 等系统属性，或 ELASTIC_APM_* 环境变量
结构化日志Logback ECS JSON（logging.structured.ecs.*）自动注入 trace.id / span.id，Kibana 可日志↔链路关联
关联字段MDC correlationId 端到端贯穿由入口（Controller/Consumer/Task）写入
Actuator 端点health, info, metrics（dev 额外 loggers）MANAGEMENT_ENDPOINTS_WEB_EXPOSURE_INCLUDE

K8s 清单也提供了纯 OTLP 方式的占位（指向 Fleet APM 的 /v1/traces、/v1/metrics、/v1/logs，采样率 0.1），可二选一。

不要双开

若启用了 Elastic APM Agent，请保持 Spring Boot 内置 exporter 关闭（management.*.export.enabled=false，prod 默认即如此），否则指标会被重复上报。

#10 上线校验

  1. 健康检查：/api/v1/actuator/health 返回 UP；/health/readiness 与 /health/liveness 就绪。
  2. 依赖连通：日志确认 PostgreSQL 连接池建立、embedding bean 绑定成功；启用 Milvus/RocketMQ 时确认无连接告警。
  3. 离线链路冒烟：导入一条商品（见 E2E 指南 §3），轮询 rag_documents.status 直到 INDEXED。
  4. 在线链路冒烟：调用 /api/v1/public/agent/turn（SSE），确认收到 turn.started → … → turn.completed 事件序列。

#11 降级开关

服务在依赖缺失时不会崩溃，而是按既定策略优雅降级——这也是最小化部署能跑通的原因。

关闭的依赖开关降级行为
MilvusRAG_MILVUS_ENABLED=false检索退化为 PostgreSQL 关键词检索（FTS/pg_trgm/ILIKE），跳过向量召回
RocketMQRAG_ROCKETMQ_ENABLED=false索引改为 进程内直接派发（RagDirectIndexEventPublisher），属性抽取同理
LLM（答案）调用失败 / 超时回退到 规则兜底答案（answerSource=rule），不影响业务结果返回
LLM（意图）调用失败 / 超时命中确定性前置路由或回退 clarify_workflow 请用户换种说法
SMTP通知开关关闭失败仅落库审计，不发邮件

#12 安全注意事项

  • 凭据零硬编码：生产配置只用 ${ENV:default} 占位符，密钥通过 K8s Secret / 环境变量注入；.env 已 gitignore。
  • 限流：写操作类入口可用注解式 @RateLimit（基于 AspectJ 切面）保护。
  • 异常不泄漏：统一 GlobalExceptionHandler，对外不返回堆栈/内部类名；SSE 错误事件经白名单化文案处理。
  • 容器最小权限：禁用提权、drop 所有 capability。
  • 密钥轮转：APM/LLM token 一旦出现在仓库历史（如 IDE 运行配置），应视为泄漏并立即轮转。
⚠️ 已知风险

仓库内 .run/RagApplication [dev].run.xml 的 VM 参数中包含一枚明文 APM Bearer Token。该文件已被提交，请尽快轮转该 token 并改用环境变量注入，不要把任何真实密钥写进运行配置或文档。
